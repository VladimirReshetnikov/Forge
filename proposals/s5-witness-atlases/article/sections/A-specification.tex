\section{Reproduction and certificate specification}
\subsection{Commands}
The producer requires SymPy; replay does not. Run these commands from the archive's \code{prototype/} directory:
\begin{lstlisting}
python -m pip install -r ../requirements.txt
python run_examples.py
python -S verify_corpus.py
python differential.py
python mutation_tests.py
python metamorphic.py
python -S verify_corpus.py ../metamorphic-corpus
python strategy_probes.py
python -m pytest -q
\end{lstlisting}
The archived results are the observations reported in this article. Re-running the scripts may replace result JSON files and alter timings or valid isolating cuts. Preserve the archive's original result directory when a bit-for-bit record of the delivered run is needed. Different valid cuts are not different mathematical answers.

An individual input can be solved and independently replayed with:
\begin{lstlisting}
python -m atlas solve ../examples/surjective_cubic/problem.json \
    --output /tmp/cubic-certificate.json
python -S -m atlas verify ../examples/surjective_cubic/problem.json \
    /tmp/cubic-certificate.json
\end{lstlisting}
A successful verification exit code means the certificate is accepted, including a certificate for a false encoded sentence. Inspect \code{closed_value} to learn the sentence's truth. \code{null} means the outer variable is free, with its truth set in \code{truth_by_x}; it is not an unknown closed verdict. An arithmetic \code{LimitExceeded} outcome is reported as \unknown{}. Other invalid input or failed acceptance returns a nonzero exit code and no accepted verdict.

The JSON decoder rejects duplicate object keys and nonfinite JSON constants. The checker performs mathematical and canonical-form validation after decoding. These controls are useful but not a claim of complete hostile-input hardening; notably, large expressions can still be expensive before a later cap is reached.

\subsection{Problem format}
A problem object has schema \code{forge.atlas.problem/1}, a diagnostic \code{name}, \code{outer} and \code{inner} quantifiers, a list of polynomials, and a formula tree. Sparse polynomial terms are sorted triples $[i,j,c]$ for $cX^iY^j$, with nonnegative integer exponents and a nonzero canonical rational string. The empty term list is zero. For example,
\begin{lstlisting}
{
  "schema": "forge.atlas.problem/1",
  "name": "inverse_hole",
  "outer": "forall",
  "inner": "exists",
  "polynomials": [[[0, 0, "-1"], [1, 1, "1"]]],
  "formula": ["eq", 0]
}
\end{lstlisting}
encodes $\forall x\exists y\;(xy-1=0)$. Rational strings such as \code{"-3/7"} are accepted; floats, \code{"2/2"}, and \code{"0.0"} are not. Atom indices are zero-based. Formula nodes are Boolean literals, sign tests, or \code{and}, \code{or}, \code{not}, and \code{implies}. The checker validates every child even if another child determines the Boolean result, so a short circuit cannot hide an invalid subtree.

\subsection{Certificate fields and their obligations}
\begin{longtable}{p{0.28\textwidth}p{0.65\textwidth}}
\toprule
Field & What replay verifies\\
\midrule\endhead
\code{factors} & Canonical nonzero nonconstant sparse polynomials; no duplicates\\
\code{factorizations} & Every original polynomial equals its scalar times its factor powers; all factor uses are accounted for\\
\code{derivative_guards} & Exactly one receipt for each positive-$Y$ factor; exact identity and nonzero guard\\
\code{pair_guards} & Exactly every unordered positive-$Y$ pair; exact identity and nonzero guard\\
\code{projection} & Exact monic square-free lcm of all guards; dense coefficients in increasing degree\\
\code{base_roots} & Complete ordered isolating cuts for real projection roots\\
\code{stacks} & Exactly one stack for every base section and sector\\
\code{sample} & A rational sample strictly inside an open base sector, or null for a root section\\
\code{y_roots} & Complete root cover of the square-free specialized fibre-boundary product\\
\code{y_samples} & One valid rational sample per open fibre sector\\
\code{signs} & Exact signs of every original specialized polynomial on each section/sample\\
\code{truths}, \code{value} & Formula evaluation and the inner quantifier fold\\
\code{selection} & A correctly typed index of a required true/false fibre cell, or null when no selector is required\\
\code{truth_by_x} & The complete vector of inner quantified truth values\\
\code{closed_value} & The appropriate outer fold, or null for free $x$\\
\code{selected_x} & A valid outer witness/counterexample cell exactly when required\\
\bottomrule
\end{longtable}

The arithmetic routines use dense low-degree-first tuples internally for univariate operations. Bivariate source and identity checks use sparse dictionaries. The file format does not serialize implementation-specific algebraic-field objects: they are reconstructed from the validated base root and the source factor coefficients. This avoids trusting a foreign minimal-polynomial cache or a mutable library handle.

\subsection{Checker order}
\begin{lstlisting}
verify(problem, certificate):
    validate_problem_and_boolean_AST(problem)
    check_all_source_factorizations()
    check_derivative_coverage_and_identities()
    check_pair_coverage_and_identities()
    recompute_projection_from_all_required_guards()
    base_roots := verify_complete_root_cover(projection)
    require exactly 2 * len(base_roots) + 1 stacks

    for each base cell:
        x := checked_rational_sample_or_selected_algebraic_root()
        fiber_poly := squarefree_product_of_nonconstant_specialized_factors()
        y_roots := verify_complete_root_cover(fiber_poly)
        check_sector_samples_against_actual_roots()
        recompute_all_original_polynomial_signs()
        recompute_formula_truths_and_inner_fold()
        validate_witness_or_counterexample_selection()

    recompute_outer_fold_or_free_parameter_truth_set()
    validate_outer_selection()
    return accepted_encoded_result
\end{lstlisting}

A production reflected checker may replace recomputation with smaller arithmetic receipts where profitable. For example, a gcd could be accompanied by divisibility identities and a coprimeness witness rather than recomputed by Euclidean reduction. Such a change requires a new soundness argument for the optimized check, not a trusted hint that the gcd routine probably agrees.

\section{Closing recommendation}
Add this as a bounded, optional \emph{algebraic quantifier worker}, not as the universal executor of Forge. Its first substantial acceptance target should be a fully kernel-checked parameter-region theorem with an isolated irrational feasible point. That target forces the implementation to earn its source bridge, complete root coverage, exceptional-fibre arithmetic, and quantifier semantics together.

Once that boundary is established, the same machinery can supply algebraic witnesses, exact counterexample regions, branch hypotheses for typed synthesis, and smaller facts for the other Forge workers. The significant capability gain is not the word ``CAD'' in the architecture diagram. It is a checked path from a nonlinear quantified source assertion to a complete finite geometric object, and from that object back to a proof or a correctly dependent witness.
