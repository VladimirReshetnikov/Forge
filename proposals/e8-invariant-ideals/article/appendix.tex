\section{Certificate schemas and small API examples}
\label{app:schemas}

\subsection{Exact polynomials}
A polynomial is a list of terms
\begin{lstlisting}
[exponent_vector, numerator, positive_denominator]
\end{lstlisting}
with nonnegative integer exponents. Rational coefficients are reduced, nonzero,
and exact. The writer sorts exponents; the decoder rejects duplicates,
noncanonical coefficients, incorrect arities, and invalid numeric types.
Mathematical equality is polynomial equality, not equality of formatted text.

\subsection{Invariant packets}
A constant packet has schema \code{forge.pullback-space/1}, a complete problem,
a generator list, and rational transition matrices. A polynomial packet has
schema \code{forge.ideal-space/1}; its problem also includes the multiplier
bound and its matrix entries are polynomials. The matrix convention is
\[
 p_i\circ T_a=\sum_j H_{aij}p_j.
\]
The caller supplies the expected problem separately to the checker. The copy in
the certificate is compared with that expected problem; it is not allowed to
define the caller's proof obligation by itself.

A minimal nonlinear example:
\begin{lstlisting}[language=Python]
import exact as ex
import ideal_space as ideal

x, y = ex.var(2, 0), ex.var(2, 1)
certificate, statistics = ideal.synthesize(
    2, 1, 1,                       # variables, generator degree, multiplier degree
    [[x, x]],                      # initial diagonal, parameterized exactly
    [[ex.mul(x, x), ex.mul(y, y)]]  # squaring transition
)
assert ideal.check(certificate['problem'], certificate)
print(statistics)
\end{lstlisting}
An empty generator list is legal but only certifies a vacuous invariant packet.
The source-level user interface should report that no useful packet was
returned, not that the target is false.

\subsection{Finite algebras}
The problem records the number of states, each constructor's name and arity, its
row-major transition table, and the set of good states. A cover certificate lists
states. A counterexample certificate lists constructor nodes with earlier child
indices and a root index. Arity checks and the earlier-index discipline are
necessary for interpreting the node list as a finite constructor tree.

\begin{lstlisting}[language=Python]
import finite_cover as fc

problem = fc.binary_tree_counts(7)
certificate, statistics = fc.synthesize(problem)
assert certificate['kind'] == 'cover'
assert fc.check(problem, certificate)
\end{lstlisting}
The transition budget's \code{unknown} output is not a certificate and is
rejected by \code{check}. Table construction and parsing need additional
production resource limits beyond this prototype's evaluation counter.

\subsection{Integer projection}
An affine parameter expression is stored as
$[b,a_1,\ldots,a_n]$, denoting $b+\sum a_ix_i$. An inequality row represents
$a\,y\le\beta(x)$; a congruence row represents
$a\,y\equiv\beta(x)\pmod m$. The certificate stores two Bezout receipts per
congruence, one for coefficient normalization and one for its CRT merge.

\begin{lstlisting}[language=Python]
import presburger as pb

problem = {
    'parameters': 1,
    'inequalities': [
        {'a': -1, 'rhs': [0, 0]},   # y >= 0
        {'a':  1, 'rhs': [10, 0]}   # y <= 10
    ],
    'congruences': [{'a': 2, 'rhs': [0, 1], 'm': 6}]
}
certificate = pb.synthesize(problem)
assert pb.check(problem, certificate)
feasible, witness = pb.evaluate_program(certificate['program'], [8])
assert feasible and pb.holds(problem, [8], witness)
\end{lstlisting}
Evaluation is intended for a program already accepted by the checker. The
concrete evaluator does not itself revalidate an arbitrary untrusted instruction
stream on every call.
