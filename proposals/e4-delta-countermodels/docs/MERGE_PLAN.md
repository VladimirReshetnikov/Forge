# Incremental merge plan

1. Add the exact IR, producers, independent replay, and retained corpus as an
   isolated experimental worker. Do not replace the existing Forge controller.
2. Compile the three supplied Lean targets in the pinned Mathlib project.
   Record exact compiler output and axiom inventories. Then compose local
   identities with the reachability theorem to prove one complete source goal.
3. Implement the deliberately small rational tuple/list reifier with proved
   denotation equations. Reject unsupported arithmetic and numerical guards.
   Prove the synchronous product/fold bridge for the actual elaborated source.
4. Connect positive results to Forge's existing candidate/conditional-candidate
   acceptance path. The Python status is never a substitute for a Lean term.
5. Add universal fold assertions to Leant's existing behavioral dispatcher.
   Keep candidate type checking and behavioral proof checking separate; preserve
   exact source identity and original candidate-search limits.
6. Add finite Kripke diagnostics through a nominal object-logic artifact type.
   Prove the finite evaluator agrees with an existing Lean IPC semantics and
   use its soundness theorem. Never return this as a proof of Not(sourceGoal).
7. Establish held-out Lean coverage and complete timing/proof-cost measurements.
   Only then choose faster elimination or SAT libraries based on measured costs.

Anti-substitution gates: local identity compilation is not the original-source
proof; a bounded test list is not a universal fold theorem; a valid different
candidate is not the original candidate; a Kripke countermodel is not a Lean
negation; and a larger-budget synthesis result does not close an unchanged-budget
verification milestone.
