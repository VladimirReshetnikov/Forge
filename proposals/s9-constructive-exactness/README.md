# Forge: Constructive Exactness

**Integral homology, certified reductions, and obstruction-aware homotopy synthesis**

Research package prepared September 15, 2026, for Vladimir Reshetnikov.
The article develops a specific extension relative to Forge revision
`58ea206bd7ad501b930add568151217bcc7f82a2`. It does not claim that Smith normal
form, algebraic Morse theory, certificate-first search, or integer lattice
solving are new ideas.

are not Lean-kernel proofs. No Lean compiler was available; there is no installed

The Lean integration is a specification, not disguised uncompiled implementation.

## What the prototype does

For a finite free integer chain segment `Z^p --A--> Z^n --B--> Z^m`, it verifies
compatible integral kernel and boundary coordinates, computes homology invariant
factors, and finds a filler of a cycle or a separating integer/modular functional.
It also computes induced maps in the retained quotient presentation.

For a bounded graded chain complex, it performs unit cancellation while retaining
explicit reduction maps `f,g,h`. For two chain maps it solves the whole coupled
integer homotopy system, or returns a dual matrix-functional obstruction.
The negative checker verifies an adjoint identity rather than rebuilding the
search-side vectorized system. Positive homotopies can be lifted through checked
reductions and replayed against the original matrices.

A negative result means that the specified integer filler or homotopy does not
exist. It does not mean that an arbitrary Lean proposition is unprovable.
Resource caps and unsupported input mean UNKNOWN/inapplicable, not impossibility.
A stalled reduction is still a valid partial reduction, not a minimality result.

## Reproduce

Python 3.10+ is expected from language features; only Python 3.13.5 was tested.
Search was tested with exactly SymPy 1.14.0. Replay has no external dependency.

```sh
cd prototype
python -m pip install -r requirements.txt
python demo.py
python run_suite.py --output ../reproduced-results
python -S replay.py ../reproduced-results/corpus.json
```

To replay the supplied corpus without loading site packages or SymPy:

```sh
cd prototype
python -S replay.py ../results/recorded/corpus.json
python -S -m unittest discover -s tests -v
```

The regeneration output is intentionally separate from `results/recorded`.
Normal-form bases can differ across backend versions while still being valid.
Timings will vary. A successful replay validates the included source problems,
not correspondence to an unprovided Lean theorem.

## Recorded evidence

656 stored certificate cases: 97 homology coordinates, 129 fillers, 65 cycle
obstructions, 48 induced maps, 72 reductions, 100 homotopies, and 145 no-homotopy
obstructions. Every stored case replays with `python -S`.

Separate units: 489 deliberately invalid controls rejected; 64 all-minors
normal-form comparisons; 24 coordinate-composition identities; 184 tiny modular
homotopy-family enumerations; 12 dependency-free unit tests; seven reduction-first
dimension experiment rows. Do not combine these into one total success count.

The largest stored matrix dimension is 24 and the largest coefficient uses
13 bits. This is a small synthetic research corpus, not a scalability benchmark.
One 288-equation/144-variable direct system is refused by the 256-equation cap;
reduction plus lifting produces a checked homotopy of its original problem.
This is not a timing speedup claim or a comparison to `grind`.

`results/recorded/cases.csv` records per-case timed proposal-call/check intervals and certificate
size. Some fixtures and transport prerequisites are prepared outside the timed
proposal call, so these columns are not full-pipeline latency measurements. `mutations.json` records rejection results; full invalid cases are
regenerated by the explicit constructors in `run_suite.py`. `oracles.json`
distinguishes the different auxiliary test kinds. No previous Forge counts are
pooled into these results.

## Limits

The checker is research code, not formally verified or security-audited. It has
explicit shape/type/input-size checks but is not a CPU or memory sandbox.
The current matrix representation is dense. Negative homotopy transport,
class-order output, universal-filling source constructors, sparse/factorized
certificates, and all Lean adapters are specified/proved where indicated, not
silently included in executed functionality. Consult the article's status ledger.

No third-party library source, fonts, or compiler binaries are bundled.
